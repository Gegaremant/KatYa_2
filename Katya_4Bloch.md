# План Развития: KatYa 2.1 (и далее)

Вы обозначили масштабный список архитектурных и функциональных задач, которые превратят Катю из умного чат-бота в полноценного агента с доступом к системе Android (AppManager, Termux, файловая система, удаленное администрирование). 

Так как это **громадный объем работы**, я сгруппировал задачи по смыслу и предлагаю план их поэтапной реализации.

## User Review Required
> [!IMPORTANT]
> Задач очень много. Пожалуйста, посмотрите на разбивку ниже и скажите, **с какого блока (или конкретного пункта) вы хотите начать работу прямо сейчас?** Я предлагаю начать с Блока 1 (Окружение и Терминал), так как он закладывает фундамент для "самостоятельности" агента.

### Блок 1: Системная Интеграция и Окружение (Android FS, Termux)
Эти пункты связаны с тем, чтобы дать Кате реальные "руки" внутри файловой системы Android и возможность устанавливать утилиты.
- **1.1 Относительные пути ФС Android:** Научим Катю понимать, что её корень (HOME) находится в `/data/data/com.termux/files/home`. Мы пропишем этот контекст в её `system_prompt` и дадим ей инструмент `execute_command`, который будет запускаться в этой директории.
- **1.2 Загрузка окружения (wget/curl):** Дадим Кате базовые скрипты (`bootstrap.sh`) или инструменты (tools) для скачивания бинарников/скриптов из сети.
- **1.3 SSH, RDP, SCP:** Мы можем создать для Кати инструменты (tools) или обучить её использовать установленные бинарники `ssh`, `scp` из-под Termux-окружения для управления удаленными машинами.
- **1.4 "Отращиваем руки" (Google Search):** Добавим инструмент веб-поиска (`web_search`), чтобы Катя могла гуглить решения, если она сталкивается с неизвестной ошибкой в bash.

### Блок 2: Импорт/Экспорт и Резервное Копирование
- **6. Полный Import/Export конфига и БД:** Напишем логику для создания `tar.gz` или `.zip` архива, содержащего `/data/data/.../data/tasks.db`, конфиги и скрипты. Будем сохранять его в `/sdcard/Download/agent_backups/` (потребуется интеграция с Android Storage Access Framework или запрос разрешения `MANAGE_EXTERNAL_STORAGE`).

### Блок 3: Интеграции со сторонними приложениями (AppManager, Google)
- **5. Интеграция с Google Calendar и Notes:** Реализуем через официальные Android Content Providers (если возможно для календаря) или через OAuth2 Google API (потребует авторизации пользователя в приложении).
- **10. API других приложений:** Реализация общения через Android Intents.
- **11. AppManager:** Если есть рут (Root) или Shizuku, Катя сможет через командную строку (su) дергать бинарники AppManager'а (например, `am` или `pm`) для заморозки/удаления трекеров.

### Блок 4: Улучшение Пользовательского Интерфейса [ВЫПОЛНЕНО] (UI) и Чата
- **2. UI Голоса и переделка:** Текущий интерфейс записи голоса и TTS будет переработан.
- **9. Авто-отправка после голосового ввода:** Настроим детектор тишины (VAD - Voice Activity Detection) для автоматической отправки сообщения, как только пользователь замолкает.
- **7. Камера в диалогах:** Добавим интеграцию с `ActivityResultContracts.TakePicture()` для фото с камеры.
- **8. Отмена квот на загрузку:** Уберем программное ограничение размера файла, но нужно будет продумать обрезку для LLM (так как 100МБ файл в промпт не влезет).
- **4. Настройка бесплатных моделей:** Упростим и сделаем понятнее экран настроек `ServicesSettings.kt`.
- **3. Вылет на вкладке Логи:** Критический баг, мы его починим в первую очередь, когда перейдем к UI (вероятно, падение из-за слишком большого объема логов в памяти Compose).
